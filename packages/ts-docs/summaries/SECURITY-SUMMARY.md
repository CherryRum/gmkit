# 安全状态

GMKitX 尚未完成项目级独立第三方安全审计。底层依赖的审计、标准向量、差分测试和单元测试都不能替代对本仓库组合实现及部署协议的评估。

## 已有防护

- 密钥、公钥、hex/base64、模式和 tag 长度做显式校验。
- SM2 解密验证 C3；SM4-GCM/CCM 验证认证标签。
- SM2 userId ENTL 按 UTF-8 字节限制，避免 16-bit 溢出。
- RNG 可配置 `warn`/`strict` 并支持注入平台安全源。
- 提供二进制解密 API，避免任意数据错误转 UTF-8。
- `constantTimeEqual` 避免常见早退比较，但 JS 运行时不能承诺严格常量时间。

## 发布阻断项

- 新增或修改标准向量不能只由本项目自身实现生成并自证。
- AEAD 篡改未拒绝、SM2 C3 篡改未拒绝、随机数静默降级、私钥进入日志，均应阻断发布。
- 依赖审计告警需按可达性和影响评估，不能只看数量，也不能直接忽略。

## 使用方责任

调用方负责密钥生成、保存、轮换、访问控制、nonce 分配、协议版本、错误处理和审计日志脱敏。高侧信道风险、长期主密钥或强合规部署应优先考虑受控 Java/native 模块或 HSM。

## 披露

安全问题请使用仓库 GitHub Security Advisories 私下报告，不要在公开 issue 中提交密钥、可利用细节或真实业务数据。
