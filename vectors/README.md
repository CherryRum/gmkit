# Shared Test Vectors

This directory contains **cross-language test vectors** consumed by both
the Java (`java/`) and TypeScript (`ts/`) implementations of gmkit.

## Purpose

Vectors here are the single source of truth for cross-language conformance.
A change to any file in `/vectors/` triggers CI in both `ts-ci.yml` and
`java-ci.yml` (via `paths:` filter). Both stacks must produce identical
bytes for the same input.

## Files

- `interop.json` — Schema-versioned set of SM2/SM3/SM4/ZUC interop vectors.
  Loaded by:
  - `ts/test/interop-compliance.test.ts` (vitest, JSON import via
    `import vectors from '../../vectors/interop.json'`)
  - `java/gmkit/src/test/java/cn/gmkit/InteropComplianceTest.java`
    (classpath resource `/vectors/interop.json`, populated by Maven
    test-resources pointing to `${project.basedir}/../../vectors`)

## Vector entry schema (excerpt)

```json
{
  "name": "sm3 digest chinese text",
  "algorithm": "SM3",
  "input": "你好，GMKit",
  "inputEncoding": "utf8",
  "output": "...",
  "outputEncoding": "hex",
  "source": "project"
}
```

`source` field rules (per `gmkit.md` 第 596–604 行):
- `"project"` — vector generated by gmkit itself for regression purposes
- `"GM/T 0004-2012"` / `"GM/T 0003-2012"` / etc. — vector reproduces an
  official 国密 standard test case; the standard ID MUST be cited verbatim
- Never fabricate a standard citation.

## RNG determinism

Some entries are deterministic (digest, fixed-key cipher). Others (SM2
encrypt, SM2 sign without `r` override) involve RNG and CANNOT be
expressed as a bit-exact output vector — for those, the test verifies
the round-trip property (encrypt → decrypt = original) rather than a
fixed ciphertext.

## Adding a new vector

1. Add the entry to `interop.json` with a stable, descriptive `name`.
2. Add a matching test case on both sides (TS in
   `ts/test/interop-compliance.test.ts`, Java in
   `cn.gmkit.InteropComplianceTest`).
3. Run both stacks locally: `cd ts && npm test` and
   `cd java && mvn -B test`.
4. Open a PR — both `ts-ci.yml` and `java-ci.yml` will trigger.
