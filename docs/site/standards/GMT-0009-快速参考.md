# GM/T 0009 快速参考

## 推荐协议配置

| 项目 | 建议 |
|:--|:--|
| userId | 双方显式约定同一个非空值，或双方都使用 `DEFAULT_USER_ID` |
| 密文模式 | 新协议优先明确指定 `C1C3C2` |
| 公钥 | 对接前明确压缩或非压缩；默认生成非压缩公钥 |
| 签名 | 明确 `raw` 或 `der`，跨 Java 系统通常需特别核对 DER |
| 编码 | 明确 hex/base64；不要只依赖自动识别 |

> 兼容提示：当前版本中，省略 `userId` 和传入空字符串都会使用 `DEFAULT_USER_ID`。空字符串不能表达真实空 ID。

这里的“推荐”是项目互操作建议，不替代标准条款或行业合规要求。协议设计应把所有项目写入可版本化载荷或双方配置，不能只依赖库默认值。

## 协议载荷检查表

| 操作 | 至少固定的字段 |
|:--|:--|
| 加密 | 协议版本、`C1C3C2`/`C1C2C3`、公钥表示、密文编码 |
| 签名 | 协议版本、非空 `userId` 或默认值约定、raw/DER、签名编码 |
| 验签 | 与签名端完全相同的 `userId`、签名格式和消息原始字节 |
| 密钥交换 | 发起方/响应方角色、静态和临时公钥、双方 ID、派生密钥长度 |

解析失败、C3 不匹配或验签失败都必须终止处理。不要在失败后尝试另一种模式并把成功结果当成同一协议的正常路径；确需迁移兼容时，应在协议版本层明确区分。

## 可运行自检

```ts
import {
  InputFormat,
  OutputFormat,
  SM2CipherMode,
  sm2Decrypt,
  sm2Encrypt,
  sm2GenerateKeyPair,
  sm2Sign,
  sm2Verify,
} from 'gmkitx';

const { privateKey, publicKey } = sm2GenerateKeyPair();
const userId = 'gmkit-release-check';
const message = 'GM/T 0009 release check';

const cipher = sm2Encrypt(publicKey, message, {
  mode: SM2CipherMode.C1C3C2,
  outputFormat: OutputFormat.BASE64,
});
const plain = sm2Decrypt(privateKey, cipher, {
  mode: SM2CipherMode.C1C3C2,
  inputFormat: InputFormat.BASE64,
});
if (plain !== message) {
  throw new Error(`SM2 decrypt mismatch: ${plain}`);
}

const signature = sm2Sign(privateKey, message, {
  userId,
  signatureFormat: 'der',
  outputFormat: OutputFormat.BASE64,
});
const verified = sm2Verify(publicKey, message, signature, {
  userId,
  signatureFormat: 'der',
  inputFormat: InputFormat.BASE64,
});
if (!verified) {
  throw new Error('SM2 DER signature verification failed');
}
```

## 二进制数据

```ts
import { sm2DecryptBytes, sm2Encrypt, sm2GenerateKeyPair } from 'gmkitx';

const { privateKey, publicKey } = sm2GenerateKeyPair();
const input = Uint8Array.of(0x00, 0xff, 0x80, 0x41);
const cipher = sm2Encrypt(publicKey, input);
const output = sm2DecryptBytes(privateKey, cipher);

if (output.length !== input.length || output.some((value, i) => value !== input[i])) {
  throw new Error('SM2 binary round-trip failed');
}
```

## 常见失败

- 签名端和验签端 userId 不一致。
- 一端使用 raw 签名，另一端按 DER 解析。
- 加密端使用 C1C2C3，解密端固定为 C1C3C2。
- 把 Base64 当 hex 传入，或把任意二进制明文用字符串解密 API 转成 UTF-8。
- 公钥和私钥不是同一密钥对；密钥交换接口会明确拒绝这种输入。
